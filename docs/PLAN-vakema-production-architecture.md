# Vakema.lt — Production-Grade Architecture Plan

## Goal

Turn the existing Vakema.lt single-file landing page (a 14 MB `index.html` with embedded base64 images, vanilla JS, no backend, no tests, no deploy pipeline) into a production-grade, tested, deployable website for a Lithuanian windows & doors company.

## Current context / assumptions

**What exists today** (recovered from the ChatGPT project export at
`C:\Users\matas\Documents\Hermes\chatgpt-projects\Vakema.lt\build\`):

- `index.html` — 14 MB, 234 lines. Bloat comes from a base64-encoded JPEG favicon (~14 MB) embedded inline. Sections: header/nav, hero with hotspots, product carousel, solutions grid, manifesto, process, contact form, footer.
- `app.js` (7 KB) — carousel logic, page-wipe transitions, mobile menu, contact form handler (form currently does nothing — no backend).

- `package.json` — Vite dev only, `"vite": "latest"` (unpinned — must be pinned).

**Assumptions** (flag to user if wrong):

1. The site is a **marketing landing page**, not a web app. No auth, no user accounts. A static/SSG architecture is correct; React/Next.js would be over-engineering.
2. The contact form needs to actually deliver leads (email + stored backup).
3. Content language: Lithuanian primary; architecture must not block adding EN later, but full i18n is YAGNI for v1.
4. Hosting target: **Firebase Hosting**, existing Firebase project **`vakema`** (confirmed by user; goes into `.firebaserc` as `"default": "vakema"`). Cloudflare Pages is the fallback if Firebase access fails.

6. Domain `vakema.lt` DNS control is available (needed for final go-live; not blocking for the build).

## Architecture / proposed approach

**Astro 5 + TypeScript, statically rendered, deployed to Firebase Hosting, with a single Cloud Function (2nd gen, Node 22) as the contact-form endpoint that writes to Firestore and sends email via Resend (or SMTP fallback).** Astro gives us zero-JS-by-default output (the current page is 99% static — the carousel/menu are the only JS), first-class image optimization (kills the 14 MB base64 problem structurally), and componentization of the existing HTML without a framework rewrite. The existing CSS moves in as-is (global stylesheet + scoped component styles). CI via GitHub Actions: lint → typecheck → unit tests (Vitest) → build → Lighthouse budget check → E2E smoke (Playwright) → deploy preview on PR, deploy prod on merge to `main`.

**Why not the alternatives:** plain Vite keeps the monolithic HTML problem; Next.js/React adds a runtime and hydration cost for a page that is a poster with a carousel; WordPress adds a server to secure and patch for zero benefit.

**Task 2.2 — Contact form validation module** `src/scripts/validate-lead.ts` (shared client + server):

```ts
export interface Lead { name: string; email: string; phone?: string; message: string; }
export function validateLead(l: unknown): { ok: true; lead: Lead } | { ok: false; errors: string[] } {
  const v = l as Partial<Lead> ?? {};
  const errors: string[] = [];
  if (!v.name || v.name.trim().length < 2) errors.push('name');
  if (!v.email || !/^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/.test(v.email)) errors.push('email');
  if (!v.message || v.message.trim().length < 10) errors.push('message');
  return errors.length ? { ok: false, errors } : { ok: true, lead: v as Lead };
}
```

**Task 3.2 — The endpoint.** `functions/src/index.ts` (complete file):

```ts
import { onRequest } from 'firebase-functions/v2/https';
import { initializeApp } from 'firebase-admin/app';
import { getFirestore, FieldValue } from 'firebase-admin/firestore';
import { defineSecret } from 'firebase-functions/params';
import { validateLead } from './validate-lead'; // copied from src/scripts by build script — single source of truth

initializeApp();
const resendKey = defineSecret('RESEND_API_KEY');
const ALLOWED_ORIGINS = ['https://vakema.lt', 'https://www.vakema.lt', 'http://localhost:4321'];

export const submitLead = onRequest({ secrets: [resendKey], region: 'europe-west1' }, async (req, res) => {
  const origin = req.headers.origin ?? '';
  if (ALLOWED_ORIGINS.includes(origin)) res.set('Access-Control-Allow-Origin', origin);
  if (req.method === 'OPTIONS') { res.status(204).send(''); return; }
  if (req.method !== 'POST') { res.status(405).json({ error: 'method_not_allowed' }); return; }

  const result = validateLead(req.body);
  if (!result.ok) { res.status(400).json({ error: 'validation', fields: result.errors }); return; }

  // honeypot: bots fill the hidden "company" field
  if ((req.body as any).company) { res.status(200).json({ ok: true }); return; }

  const doc = await getFirestore().collection('leads').add({
    ...result.lead,
    createdAt: FieldValue.serverTimestamp(),
    ua: req.headers['user-agent'] ?? null,
  });

  await fetch('https://api.resend.com/emails', {
    method: 'POST',
    headers: { Authorization: `Bearer ${resendKey.value()}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({
      from: 'svetaine@vakema.lt',
      to: ['info@vakema.lt'],
      subject: `Nauja užklausa: ${result.lead.name}`,
      text: `${result.lead.name}\n${result.lead.email}\n${result.lead.phone ?? '-'}\n\n${result.lead.message}\n\nFirestore: ${doc.id}`,
    }),
  });

  res.status(200).json({ ok: true });
});
```
